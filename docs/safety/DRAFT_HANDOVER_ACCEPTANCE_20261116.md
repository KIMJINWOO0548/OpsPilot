# OpsPilot 원본 수용 장부 · OP1 / OP2 / OP7

2026-11-16 · 감자 Windows PC · 기준 `dd4bc206` · [정책과 API 계약](../decisions/ADR-005-DRAFT-HANDOVER.md)

바탕화면 패키지는 Git 체크아웃이 아니며 설치기 소스에 별도 변경이 있다. 원본 및 개선본 기존 체크아웃의 추적 파일과 미추적 로그를 그대로 두고, 원격 `improve/reliability-review-20261116`과 일치한 기준 SHA에서 별도 작업공간을 만들었다. 이 변경은 기존 Windows 호스트·설치기·패키징 파일을 포함하지 않는다.

| 원본 항목 | 구현 및 검증 경계 | 남은 조건 |
|---|---|---|
| OP1 초안 생성 멱등성 | 작성자 범위 요청키+입력 SHA-256, SQLite 단일 커밋, 동시 처리·다른 입력 409·ACL 재검증·시간이 지난 재시도. 서버에 미완료 요청을 먼저 저장. 실제 데스크톱 API를 종료/재시작하고 같은 ID·생성 감사 한 건·실행 0건 확인. | 키를 보내지 않는 기존 외부 호출에는 중복 방지를 약속하지 않는다. 운영 다중 노드 수용은 별도다. |
| OP2 승인자 인계 | 현재 서버 세션·승인 역할 재검증, 같은 팀의 다른 승인자만 인계, 버전·fingerprint 검사. 사유/담당자/상태/버전의 감사 저장과 인계를 함께 커밋. 미실행 건은 재승인, 불확실 건은 조회만. 명시 취소·계정 회수·오래된 복원을 시험. | 승인자 부재는 이유를 남기는 사람의 판단이다. 자동 위임·외부 계정 관리·실제 독립 인력 검증은 없다. |
| OP7 원천→초안→승인/인계→응답 유실→재조정 | 합성 A-103에 문서 ID·조치·상태 예상값을 명시. 승인과 인계 경쟁, 감사 쓰기 실패 롤백, 오래된 근거, 영수증 부재 및 백업 이후 실행을 재현. UNKNOWN에 새 모의 작업을 발행하지 않고 유효한 원래 영수증만 확인. 기존 조사·승인함 버튼과 연결. | 외부 시스템, 권한 원장·외부 실행 이력의 운영 복구 대조, 새 설치물 GUI 수용, OP3·OP5·OP6는 미완료. |

검사 소스: `tests/test_draft_handover_acceptance.py`, `tests/test_approval_revocation.py`, `tests/test_draft_process_restart.py`, `tests/test_database_backup.py`, `web/src/helpers.test.ts`. 먼저 8개 원본 미충족과 승인 직전 회수 경쟁을 재현했다. 복원 18개, 별도 API 수용 사례 17개, 실제 프로세스 재시작과 권한/포트 검사 3개를 각 집중 검사에서 확인했다. 과거 receipt 220개 보고서는 이 변경의 통과 근거가 아니다.

검증 대상은 로컬 임시 SQLite 및 합성 계정이다. G0/G1 연구·95점·공개 배포를 입증하지 않는다. Windows 네이티브 소켓에서 간헐적으로 10014가 발생했으며 기준 재실행의 219 통과/1 오류도 보존했다. 최종 실행 결과 및 SHA 검증은 작업 기록을 참조한다.

# 로컬 G2 데모 디자인 점검

2026-10-19 (Asia/Seoul). Product Design audit 흐름으로 in-app browser의 `http://127.0.0.1:8000/`를 직접 조작하고 저장한 화면을 검토했다. UI 코드는 변경하지 않았다. 합성 자산 A-103과 모의 engineer/approver만 사용했다.

## 사용자 목표와 관찰 범위

현재 근거와 시점을 확인하고 초안 생성→사람 승인→mock 실행 응답 유실→영수증 조회로 복구하는 경로를 검토했다. 일반 화면 폭 약 1265px에서 관찰했으며 아래 2~6은 전체 페이지 캡처다. 첫 화면은 초기 viewport 캡처라 하단 승인 영역은 포함하지 않는다.

| 단계 | 수행 내용 | 관찰된 상태와 평가 |
|---|---|---|
| 1 | 초기 화면 | 실행 버튼 비활성, 로컬 데모/인증 부재 안내가 보임. 정상. |
| 2 | 근거 분석 실행 | `SUPPORTED`, SOP-A103-v2 인용, 초안 버튼 활성. 동작 정상, 핵심 내용이 긴 JSON 안에 있음. |
| 3 | 작업 요청 초안 생성 | `PENDING_APPROVAL`, 승인·거절 활성, 실행 비활성. 승인 전 경계가 화면에 드러남. |
| 4 | 모의 approver 승인 | `APPROVED`, 실행·응답 유실 버튼 활성. 정상이나 승인 요약에서 action/근거가 생략됨. |
| 5 | 응답 유실 주입 | `UNKNOWN_RECONCILE`, 영수증 null, 복구 버튼 활성. 복구 버튼보다 실행 버튼이 시각적으로 강조됨. |
| 6 | 상태 확인으로 복구 | `SUCCEEDED`, 영수증 표시. 정상이나 성공 후에도 복구·실행 버튼이 활성 상태로 남음. |

## UI01 후속 작업

| 우선순위 | 관찰 근거 | 최소 개선 |
|---|---|---|
| 높음 | 2~6: 영문 상태값·체크섬·원시 JSON이 주요 결과임 | 조치·판정 이유·근거 버전·승인 상태를 한국어 요약으로 먼저 표시하고 원시 상세는 펼쳐 확인하게 한다. |
| 높음 | 5: 복구가 가능해져도 실행 버튼이 더 강조됨 | 응답 유실 상태에서는 영수증 조회가 다음 행동임을 명확히 안내하고 복구를 주 버튼으로 표시한다. 실제 중복 방지는 서버 정책으로 유지한다. |
| 보통 | 2~6: 입력은 한국 현지 시각, 결과는 UTC `Z`이며 시간대 안내 없음 | 유효 시점/알려진 시점의 의미와 표시 시간대 KST/UTC를 함께 안내한다. |
| 보통 | 3→4: 승인 영역에서 action·근거가 상태/id로 대체됨 | 승인 대상 조치와 근거 버전을 완료 이후에도 요약에 유지한다. |
| 보통 | 6: 성공 뒤에도 복구와 실행이 활성, 성공 설명은 JSON뿐 | 완료 상태·영수증과 재조회/재시도의 의미를 문장으로 안내한다. |
| 보통 | 접근성 트리에서 자산·날짜 입력의 명시적 이름이 보이지 않음. 코드의 label에도 for 연결 없음 | label의 for/id 연결 및 결과 상태 live region을 보강한 뒤 키보드·스크린리더로 검증한다. |

단계 표시, 승인 전 실행 버튼 비활성화, 모의 인증·로컬 한계 고지는 유지할 장점이다. 색상 대비 수치, 스크린리더, 키보드 전체 경로, 작은 화면, 오류·거절·다른 자산 분기는 이번 화면 점검에서 검증하지 않았다. 스크린샷만으로 WCAG 준수를 주장하지 않는다. Figma 대상 파일이 없고 Canva는 재인증이 필요해 외부 캔버스 작업은 수행하지 않았다.

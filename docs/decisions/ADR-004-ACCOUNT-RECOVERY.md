# ADR-004: 로컬 계정 회수와 일관된 DB 복구 경계

2026-10-22. 배포 준비의 다음 최소 범위다. 인증 콘솔에는 계정 생성만 있고 관리자 회수 경로와 검증된 백업 절차가 없었다. 사용자 요청 범위의 구현·임시 테스트만 수행하며 기존 계정·자격증명·배포 DB를 실제 변경하지 않는다. 외부 서비스·새 의존성은 추가하지 않는다.

## 계정 회수

기존 users에 `disabled` 상태를 호환 migration으로 추가한다. CLI `--action disable`은 계정을 비활성화하고 세션을 같은 트랜잭션에서 폐기한다. `--action revoke-sessions`는 세션만 폐기해 비밀번호가 유효하면 새 로그인은 허용한다. 재활성화·비밀번호 재설정·공개 관리 API는 이번 범위가 아니다. 기존 create 명령은 유지한다. 알 수 없는 계정은 성공으로 위장하지 않는다.

로그인 해시 계산은 오래 걸리므로 DB 쓰기 lock을 잡지 않고 계산하되, 세션을 넣는 직전 쓰기 트랜잭션 안에서 계정 활성 상태와 현재 credential hash를 다시 검사한다. hash 검사 도중 계정 회수/세션 폐기가 발생해도 나중에 새 세션이 발행되지 않도록 세션 세대 번호를 함께 비교한다. 회수 이전에 이미 시작된 요청을 OS 수준에서 취소하는 보장은 하지 않는다. 매 새 HTTP 요청의 세션 검증은 비활성 계정을 거부한다.

## 백업과 복원

SQLite 표준 backup API로 일관된 복사본을 만든다. 새 목적지만 허용하고 overwrite를 거부한다. 임시 파일에서 integrity_check·필수 테이블을 검증한 뒤 목적지로 게시하며 실패 시 partial 파일을 정리한다. restore도 새 목적지만 허용한다. 실제 기존 DB를 덮어써야 하는 운영 전환은 사람이 서버 종료·경로·백업을 확인한 뒤 수행한다. 백업은 계정 hash/session/evidence/audit/receipt를 포함하는 민감 파일이며 파일 접근 통제와 보존은 별도 운영 책임이다.

## 검증·제약

계정 회수·다른 계정 독립성·session replay 거부·폐기 후 정상 재로그인·hash 계산 중 회수 race·legacy users migration을 실패 테스트부터 구현한다. 백업은 정상 복원/원문 보존·기존 목적지 보존·손상 DB 거부·실패 cleanup·필요 테이블 검증을 실행한다. local SQLite 범위이며 IdP/SSO·다중 노드 세션 폐기·암호화 백업·외부 운영 재해 복구 SLA를 달성했다고 주장하지 않는다.

# ADR-005: 초안 요청키와 승인 담당자 인계

2026-11-16 · OP1/OP2/OP7 · 기준 `dd4bc206`.

- 초안 요청키(`Idempotency-Key`)의 범위는 tenant/team/작성자다. UTC 정규화한 두 시점·자산·claim의 SHA-256과 초안 ID를 같은 SQLite 트랜잭션에 저장한다. 입력의 사용자 주장 actor는 무시한다. 동일 키와 입력은 기존 ID, 다른 입력은 409. 키 없는 이전 호출은 호환 유지한다. 재조회는 현재 인증·ACL을 적용하며 아직 작성하지 않은 요청에는 기존 1시간 제한을 적용한다. 실행 키와 별개다.
- 기존 콘솔은 `/api/v1/draft-intent`로 초안 생성 전에 요청키와 입력을 서버에 저장한다. 작성자 범위에 미완료 요청 하나만 유지하고, 현재 창이나 로컬 포트가 바뀌어도 다시 조회할 수 있다. 성공 또는 생성되지 않았음이 확실한 검증 실패 이후에만 키를 명시적으로 정리한다. 저장된 초안이 없는 상태에서 정리한 `intent:` 키로는 새 초안을 생성할 수 없다. 응답을 받지 못하면 같은 요청으로 재시도한다.
- 같은 팀의 활성 승인자가 사유를 남겨 자신에게 인계한다. 작성자는 불가하다. 부재 여부는 운영자의 판단이며 자동 감지하지 않는다. 인계에 대상 fingerprint와 검토 버전이 필요하다. 결정/인계가 같은 잠금에서 경쟁하며 오래된 버전은 거부한다. 승인 전에는 서버 세션과 실제 역할·소속을 다시 확인한다.
- 인계 후 미실행 초안은 새 담당자의 명시적 승인이 필요하다. 근거·조치 변경 시 기존 승인을 사용하지 못한다. UNKNOWN의 인계는 영수증 확인 권한만 넘기며 작업을 다시 실행하지 않는다. 인계 이벤트는 이전·이후 담당자/상태·사유·시각·버전·fingerprint와 함께 원자적으로 저장한다.
- 실행 전 원 승인자는 대상 버전·fingerprint가 일치하고 영수증이 없는 승인만 취소할 수 있다. 승인 시 계정의 회수 세대를 저장하며 세션 폐기 또는 계정 비활성화 후에는 새 로그인만으로 원래 승인을 사용할 수 없다. 기존 승인에는 세대 0을 요구한다.
- 백업에 이후의 권한 취소·실행 이력이 없으므로 지원 복원 경로에서 모든 저장 계정을 격리하고, 대기 초안은 만료, 승인된 건은 UNKNOWN으로 내린다. 기존 영수증·감사는 보존한다. 운영자가 최신 권한과 실행 이력을 대조하기 전에는 운영 전환하지 않는다. 파일을 수동 복사해 복원하는 경로는 지원하지 않는다.
- 실제 외부 API 쓰기, 원천 등록·수정·폐기 UI, 운영 규모 검증은 이번 범위 밖이다. 로컬 SQLite의 mock 원장만 사용한다.

# 3분 시연 순서와 설명 가능한 주장

계정 준비·실행은 [배포 안내](DEPLOYMENT.md), 기술 선택은 [ADR-003](decisions/ADR-003-SECURE-CONSOLE.md)를 따른다. 아래는 시연 대본이며 실제 촬영한 영상은 아직 없다.

1. **문제 (20초):** “문서의 업무상 유효 시점과 시스템이 알게 된 시점을 분리합니다. 나중에 들어온 정정 문서를 과거 판단에 섞으면 잘못된 조치가 생길 수 있습니다.”
2. **정상 조사 (30초):** engineer로 A-103 현재 분석. 센서 진단 우선·SOP v2·문서 위치·checksum을 보여준다. 타임라인에서 v1/v2의 유효 구간과 관측 시점을 나란히 설명한다.
3. **시간/충돌 (40초):** A-104를 유효/관측 모두 2026-09-20 10:00 KST로 분석하면 수동 점검 v1이다. 현재 시점에는 정정 v2가 사용된다. 과거 결과의 초안은 읽기 전용이다. A-105는 두 SOP가 모순이라 조치가 없고 초안이 차단된다.
4. **실행 통제 (50초):** 현재 A-103을 재분석해 초안을 만든다. 작성자의 승인 버튼이 잠긴 것을 보여주고 로그아웃한다. 독립 reviewer로 로그인해 초안 hash·근거를 검토하고 승인한다. 응답 유실 시나리오를 실행한 뒤 영수증 복구로 SUCCEEDED를 확인한다. 같은 영수증 멱등성은 자동 회귀 테스트 근거로 설명한다.
5. **증빙과 한계 (40초):** 자동 테스트·실패 사례·ADR를 보여준다. “React/FastAPI/SQLite와 결정적 정책, 서버 계정 인증을 구현했습니다. 외부 모델·RAG 품질 비교·분산 outbox·기업 운영 배포 검증은 아직 없습니다. 합성 smoke를 정확도로 제시하지 않습니다.”

실제 데이터/독립 평가 없이 개선율·95점·수상·운영 성과를 적지 않는다. 채용 제출 설명은 현재 구현과 재현 증거를 중심으로 하고, [점수표](PORTFOLIO_SCORECARD.md)의 보류 상태를 유지한다.
